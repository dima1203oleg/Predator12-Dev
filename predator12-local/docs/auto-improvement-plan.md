# План автоматичного покращення Predator Analytics

Мета: налаштувати інструменти в репозиторії так, щоб вони автоматично знаходили дефекти, пропонували виправлення, генерували й тестували зміни, і робили це з перевагою на безкоштовні або локальні рішення там, де це можливо. Нижче — практичний, поетапний план з конкретними кроками, налаштуваннями та прапорцями безпеки.

## 1) Ознайомлення з воркфлоу
- Основні оркеструючі елементи: `backend/app/agents/supervisor.py` — центральний супервайзер агентів; `backend/app/agents/registry.yaml` — реєстр агентів і моделей.
- Сигнали для автоматизації: авто-лікування (`SelfHealingAgent`), моніторинг моделей (`ModelMonitorAgent`), AutoImproveAgent — ідеальні місця, щоб підключити автоматичні пропозиції коду.

## 2) Основні напрямки автоматизації (стратегія)
1. Статичний аналіз + автозаміни: ESLint/Prettier (frontend), black/isort/mypy (backend). Запускати локально та в CI. Автозастосування правил — через `editor.codeActionsOnSave` і pre-commit hooks.
2. Unit / Integration tests as gates: кожен автопропозиційний PR повинен запускати `pytest` та фронтенд-тести. CI відхиляє PR, якщо тест не проходить.
3. Автогенерація патчів: використовувати локального/безкоштовного агента (наприклад, `saoudrizwan.claude-dev` у поєднанні з локальними LLM або Codeium) для створення pull request-ів з описом змін. Вмикати автогенерацію тільки як suggestion/PR (не автозлиття).
4. Моніторинг моделей і самооптимізація: інтегрувати `AutoImproveAgent` з пайплайнами перевірки метрик (в `backend/app/agents/tasks/`) — при виявленні деградації агент створює задачу на retrain або PR з пропозицією коду/конфігурації.

## 3) Конкретні автоматичні потоки (how-to)
A. Local developer loop (fast):
- Формат/лінт при збереженні (налаштовано в `.vscode/settings.json`).
- `pre-commit` hooks: запускають black/isort/mypy/eslint/unit-tests (треба додати, якщо немає).

B. CI pipeline (required):
- Workflow: `lint -> tests -> build -> artifact`.
- При успіху: бот створює PR з навчальними/оптимізаційними змінами, додає детальний changelog і тест-результати.

C. Autonomous suggestion agent (safe mode):
- Agent запускає локальний dry-run: застосовує пропозиції в окремому робочому каталозі, запускає тести, збирає звіт. Якщо тести пройдені — генерує PR з описом.
- Важливе правило: ніколи не мерджити автоматично в `main` — лише створювати PR з міткою `autogenerated` та чеклістом безпечної перевірки.

## 4) Безкоштовні / низькозатратні опції
- Використати Codeium (free) або локальні LLM (LlamaX, Mistral OSS), які можна розгорнути локально для генерації патчів.
- Використовувати існуючі інструменти: `saoudrizwan.claude-dev` (встановлений) для генерації ідей/патчів, але вимагати підтвердження вручну перед PR.

## 5) Guardrails та безпека
- Заборонити автоматичне мердження в production гілки.
- Включити тестові застави (smoke tests) і статичний аналіз перед створенням PR.
- Логування дій агента та можливість audit/відкату.

## 6) Набір файлів/скриптів, які я рекомендую додати (low-risk)
1. `.vscode/settings.json` — вже додано (налаштування inline suggestions, format on save).
2. `scripts/auto_propose.sh` — оболонка, яка викликає агента, запускає тести та створює PR (placeholder — реалізуємо при підтвердженні).
3. GitHub Actions: `ci/lint-and-test.yml` (лінт + тести) і `ci/autogen-scan.yml` (періодичний скан, створення PR пропозицій).

## 7) Наступні кроки, які я можу виконати зараз
1. Додати `pre-commit` конфіг і GitHub Actions для лінту/тестів (швидко і безпечно).
2. Створити шаблон скрипту `scripts/auto_propose.sh` і робочий GitHub Action, який виконує його в sandbox (не мерджить нічого).
3. Підключити місцеві вільні моделі або Codeium як fallback для агентової автогенерації (вказати як опцію в docs).
